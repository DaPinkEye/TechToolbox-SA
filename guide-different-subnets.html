NETWORKING GUIDE

Why can devices on different subnets communicate?

Routers, gateways and routing explained simply

Devices on the same subnet can talk directly to each other using ARP and Layer 2 switching. Devices on different subnets cannot do this — they need a router (or Layer 3 switch) to forward the traffic.

The role of the default gateway

When a device wants to send a packet to an IP that is not on its own subnet, it looks at its routing table. In almost every normal computer, phone or camera the only route is:

“If the destination is not on my local network → send it to the default gateway.”

The default gateway is almost always the router’s IP address on that subnet (commonly .1 or .254).

What the router does

  1. Receives the packet from the source device
  2. Looks at the destination IP
  3. Checks its own routing table to see which interface (or next hop) should be used
  4. Forwards the packet out of the correct interface
  5. The process continues until the packet reaches the destination subnet

Simple real-world example

Office network:

  • Staff PCs: 192.168.10.0/24 — gateway 192.168.10.1
  • CCTV cameras: 192.168.20.0/24 — gateway 192.168.20.1

Both gateways are interfaces on the same router (or firewall). When a PC at 192.168.10.50 wants to reach a camera at 192.168.20.15:

  1. PC realises 192.168.20.15 is not local → sends packet to 192.168.10.1
  2. Router receives it, sees the destination is on the 192.168.20.0/24 network
  3. Router forwards the packet out of its 192.168.20.1 interface
  4. Camera receives the packet and can reply the same way

When communication fails

Common reasons devices on different subnets cannot talk:

  • Wrong or missing default gateway on one of the devices
  • Router does not have a route to the destination network
  • Firewall / ACL is blocking the traffic
  • One of the devices has an incorrect subnet mask
  • VLAN misconfiguration (devices are isolated at Layer 2)

Quick field checklist

  1. Can the device ping its own gateway?
  2. Can the device ping the far-side gateway?
  3. Can the device ping the final destination?
  4. Check the subnet mask and gateway on both ends
  5. Check routing table or firewall rules if the first three fail

Understanding this flow is one of the most useful skills for any network or CCTV technician.
